Q1: How does your pipeline enforce Shift-Left security, and what PCI-DSS v4.0 requirement does it satisfy?
Phani: "In Phase 1, the CodePipeline invokes AWS CodeBuild running Checkov for Infrastructure as Code static analysis and detect-secrets for credential scanning before any Terraform plan is applied. Q2: Why was Amazon Inspector integrated into the container deployment gate instead of scanning only in the registry?
Phani: "Amazon Inspector v2 provides continuous vulnerability management. By implementing phase2/inspector_gate.py inside CodeBuild right after docker push, we create an automated policy guardrail. If an image contains any CRITICAL or HIGH CVEs, the script exits with status 1, preventing the pipeline from advancing and stopping the rollout of vulnerable containers to ECS Fargate."
Q3: What makes the Network Firewall Prefix List integration dynamic?
Phani: "We created customer-managed prefix list phani-threat-ips (pl-0b2d6049684e69a1a) and referenced it in our Suricata stateful rule group using drop ip @BETA any -> any any. When security teams add malicious IP addresses to the prefix list, AWS Network Firewall automatically updates active inspection without needing policy redeployments or firewall downtime."
Q4: Walk me through the automated SOAR incident response workflow in Phase 4.
Phani: "When GuardDuty detects a portscan (Recon:EC2/Portscan), Amazon EventBridge filters the event and triggers Lambda phani-runtime-soar. Crucially, before cutting network access, the Lambda sends an SSM Run Command (AWS-RunShellScript) to capture volatile system state: process trees, network sockets, routing tables, and memory acquisition. The triage artifacts are uploaded to AES-256 encrypted S3 bucket phani-fintech-forensics-435023701114. Only then does the Lambda modify the instance's Security Group to phani-quarantine-sg, revoking all outbound egress to sever attacker command-and-control while retaining SSH port 22 for forensic investigators."
